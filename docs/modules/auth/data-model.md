# مدل داده‌ی ماژول auth

فایل: `src/server/db/schema/auth.ts`.

## rate_limit_hits

محدودیت نرخ روی PostgreSQL با پنجره‌ی زمانی ثابت (Tech §2.8، §7.6). مایگریشن: `0002_rate_limits`.

| ستون           | نوع         | قاعده                                                             |
| -------------- | ----------- | ----------------------------------------------------------------- |
| `key_hash`     | text        | SHA-256 از «نام قاعده + کلید»؛ شماره یا IP هرگز خام ذخیره نمی‌شود |
| `window_start` | timestamptz | شروع پنجره، از زمان خود پایگاه داده؛ ایندکس برای پاک‌سازی         |
| `count`        | integer     | تعداد درخواست در این پنجره                                        |

کلید اصلی: (`key_hash`, `window_start`). شمارش با یک upsert اتمی است، پس درخواست‌های هم‌زمان یک شمارنده را می‌بینند. کار روزانه‌ی `auth.prune-rate-limits` (۰۰:۳۰ UTC) پنجره‌های قدیمی‌تر از یک روز را حذف می‌کند.

## otp_challenges

هر درخواست کد ورود (MVP §5 OTPChallenge، Tech §7.3). مایگریشن: `0004_otp_challenges`.

| ستون          | نوع         | قاعده                                                                      |
| ------------- | ----------- | -------------------------------------------------------------------------- |
| `id`          | uuid (v7)   | در کد ساخته می‌شود تا hash به آن گره بخورد                                 |
| `phone_e164`  | text        | شماره‌ی نرمال‌شده؛ ایندکس با `created_at`                                  |
| `code_hash`   | text        | HMAC-SHA256 با `AUTH_OTP_SECRET` روی «شناسه:کد»؛ خود کد هرگز ذخیره نمی‌شود |
| `expires_at`  | timestamptz | ۲ دقیقه بعد از ساخت، از زمان پایگاه داده                                   |
| `consumed_at` | timestamptz | پس از تأیید موفق (PK-028)؛ یک‌بارمصرف                                      |
| `attempts`    | integer     | تعداد تلاش‌های تأیید؛ حداکثر ۵ (PK-028)                                    |
| `created_at`  | timestamptz |                                                                            |

محدودیت درخواست (مقادیر اولیه؛ سند عدد نداده است): هر IP ۲۰ بار در ساعت، هر شماره یک بار در دقیقه (همان شمارش معکوس ارسال دوباره) و ۵ بار در ساعت.

## auth_sessions

نشست ورود میزبان (Tech §7.3؛ Tech §8 با نام AuthSession تا با Session رویداد قاطی نشود). مایگریشن: `0005_auth_sessions`.

| ستون                         | نوع         | قاعده                                                   |
| ---------------------------- | ----------- | ------------------------------------------------------- |
| `id`                         | uuid (v7)   | کلید                                                    |
| `user_id`                    | uuid        | FK → users، با حذف کاربر حذف می‌شود؛ ایندکس             |
| `token_hash`                 | text        | SHA-256 توکن ۲۵۶بیتی کوکی؛ یکتا. خود توکن ذخیره نمی‌شود |
| `expires_at`                 | timestamptz | ۳۰ روز، با هر استفاده جلو می‌رود (PK-028 بخش دوم)       |
| `revoked_at`                 | timestamptz | خروج از این دستگاه یا همه‌ی دستگاه‌ها (PK-029)          |
| `last_used_at`، `created_at` | timestamptz |                                                         |

**تأیید کد (PK-028):** تلاش اول به‌صورت اتمی شمرده می‌شود؛ کد منقضی (`OTP_EXPIRED`)، بیش از ۵ تلاش (`OTP_ATTEMPTS_EXCEEDED`)، کد اشتباه یا استفاده‌شده یا ناشناخته (همه `OTP_INVALID` تا چیزی لو نرود). مصرف یک‌باره در همان تراکنشی است که حساب و نشست ساخته می‌شود؛ از دو تأیید هم‌زمان فقط یکی موفق است. هر شماره ۱۵ تلاش تأیید در ساعت دارد، روی همه‌ی درخواست‌هایش.

**کوکی نشست:** `pk_session`، httpOnly، SameSite=Lax، Secure بیرون از محیط local، بدون Domain (فقط روی دامنه‌ی پنل) و فقط در Server Actionهای دامنه‌ی پنل نوشته می‌شود (`src/app/_lib/auth.ts`). هر درخواست توکن را با پایگاه داده چک می‌کند (`resolveSession`) و انقضای ۳۰روزه را حداکثر ساعتی یک بار جلو می‌برد. صفحه‌ی اصلی دامنه‌ی پنل (`/`) روی سرور تصمیم می‌گیرد: با نشست به `/events`، بدون نشست به `/login`.
